## 클로드 코드 v2.1.246, 와일드카드 권한 규칙 경고와 API 키 유출 버그 수정

어제(8/25) 나온 이 릴리즈는 기능 추가보다 안정성·보안 쪽에 무게가 실렸다. 총 61개 변경사항(수정 44개, 개선 8개, 보안 관련 6개, 신규 기능 2개, 성능 개선 1개) 중 눈에 띄는 건 두 가지다. 첫째, `Bash(git * main)`처럼 서브커맨드 앞에 와일드카드(`*`)를 넣는 방식으로 Bash 허용 규칙을 짜면 의도치 않게 서브커맨드 앞에 삽입된 옵션까지 매칭돼버리는 문제가 있었는데, 이제 이런 규칙을 쓰면 시작 시 경고가 뜬다. 권한 규칙을 세밀하게 짜본 사람이라면 한 번쯤 걸려봤을 함정이다. 둘째, 서드파티 게이트웨이용으로 발급한 API 키가 앤트로픽 텔레메트리로 새어나가던 버그를 고쳤다. 사용자가 직접 넣은 키가 원래 목적지가 아닌 곳으로 흘러갔다는 건 가볍게 넘길 문제가 아니라서, 게이트웨이를 물려 쓰는 팀이라면 업데이트를 서두를 만하다. 이 외에도 `/permissions`에 오토 모드 분류 규칙을 보고 편집할 수 있는 Auto mode 탭이 새로 생겼고, 터미널 창 크기를 조절한 뒤 풀스크린 모드에서 트랜스크립트가 빈 화면으로 남는 버그, base64 문자열처럼 아주 긴 한 줄짜리 diff가 있을 때 트랜스크립트가 심하게 느려지던 버그도 함께 고쳤다.

## 포브스 "바이브코딩은 누가 만드는가를 민주화한다"… 그 이면의 92% 대 29%

포브스 테크 카운슬에 그저께(8/24) 실린 칼럼은 바이브코딩의 진짜 의미를 "코드를 안 쳐도 된다"가 아니라 "도메인 지식을 가진 사람과 실제로 만드는 사람이 같은 사람이 될 수 있게 됐다"는 데서 찾는다. 예전에는 문제를 가장 잘 아는 사람(현업 담당자)과 그걸 코드로 옮기는 사람(엔지니어) 사이에 요구사항 문서와 디스커버리 미팅이라는 번역 계층이 있었는데, 이 계층이 사라지고 있다는 것이다. 칼럼은 동시에 플랫폼을 만드는 쪽의 책임도 달라졌다고 짚는다. 예전에는 리스크 판단을 스스로 할 줄 아는 엔지니어를 위해 도구를 만들면 됐지만, 이제는 "그 판단은 이미 누군가 처리해줬을 것"이라 믿고 쓰는 현업 리더들을 위해 도구를 만들어야 한다는 것. 이 낙관적인 진단은 최근 나온 업계 통계와 나란히 놓고 보면 더 흥미롭다. 여러 조사를 종합하면 미국 개발자의 하루 채택률은 92%에 달하지만, 그 코드를 실제로 신뢰한다고 답한 비율은 29%에 그친다. "누구나 만들 수 있게 됐다"는 낙관과 "만들어진 걸 믿기는 어렵다"는 불안이 같은 시기에 나란히 커지고 있는 셈이다.

## 오늘의 생각

이번 주 초 나온 v2.1.246의 변경 목록을 다시 보면, 신규 기능 2개에 보안 수정 6개라는 비율이 상징적이다. 도구가 널리 쓰일수록 "새 걸 더 얹는 일"보다 "이미 있는 구멍을 막는 일"이 커진다는 뜻이니까. 포브스 칼럼이 말하는 "번역 계층이 사라진다"는 낙관도 결국 이런 자잘한 보안 수정들이 쌓여 도구를 믿고 맡길 수 있을 때에야 성립하는 이야기다. 92%가 매일 쓰지만 29%만 신뢰한다는 숫자는, 바이브코딩이 "누가 만드느냐"의 문제는 이미 풀었어도 "만든 걸 얼마나 믿을 수 있느냐"의 문제는 아직 한참 남았다는 걸 보여준다. 그 격차를 좁히는 건 화려한 발표가 아니라 오늘처럼 조용히 올라오는 패치 노트 한 줄 한 줄일 거다.
