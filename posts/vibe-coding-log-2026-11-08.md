**작성: 2026-11-08 09:00 (KST)**

이번에는 거대한 뉴스 하나보다는, 지난 며칠 사이 조용히 올라온 릴리즈 노트 몇 개를 모아봤다. 큰 발표는 없었지만 "매일 코드를 짜는 사람" 입장에서는 오히려 이런 디테일들이 체감이 더 크다.

## 클로드 코드, 셸/웹 도구가 내 이메일 주소를 보내기 전에 한 번 물어본다

클로드 코드 공식 체인지로그를 보면 11월 3일 올라온 2.1.317 버전에 눈에 띄는 변경 사항이 하나 있다. 웹이나 셸 도구 호출이 사용자 계정의 이메일 주소를 네트워크로 전송하려 할 때, 이제는 그 전에 확인을 묻는다는 것이다. 지금까지는 에이전트가 어떤 스크립트나 API 호출 과정에서 로그인된 계정 이메일을 그대로 흘려보내도 딱히 막을 방법이 없었는데, 이걸 권한 체크 레이어에 넣은 셈이다. 같은 날짜 변경 목록에는 Agent SDK 훅 콜백에 `onFailure: "block"` 옵션이 추가된 것도 있는데, 훅이 실패했을 때 그냥 넘어가지 않고 작업을 멈추게 할 수 있다는 뜻이라 안전장치 성격이 비슷하다.

이어서 11월 4일 2.1.318, 11월 6일 2.1.319까지 보면 흐름이 좀 더 보인다. 2.1.318에서는 클로드가 호스팅하는 클라우드 세션에 "저장소 없음(No repository)" 옵션이 생겼고, IDE 터미널에서 실행했을 때는 더 이상 IDE 확장을 자동으로 설치·업데이트하지 않도록 바뀌었다. 그리고 2.1.319에서는 MCP 작업을 터미널에서 백그라운드로 돌려놓고 끝나면 알려주는 기능과, `permissions.denyInsteadOfPrompting` 설정이 추가됐다. 이름 그대로 원래는 권한 프롬프트가 뜰 상황인데, 이 설정을 켜두면 묻지 않고 바로 거부해버리는 옵션이다. 자동화 파이프라인에서 사람이 매번 프롬프트에 응답할 수 없는 환경이라면 꽤 유용할 것 같다.

## 클로드 엔터프라이즈, 보안 센터·추론 훅 정식 출시 + IP 허용목록 자체 관리

11월 5일에는 앤트로픽 공식 블로그에 "클로드 엔터프라이즈 보안팀을 위한 가시성·제어 강화"라는 글이 올라왔다. 핵심은 세 가지다. 첫째, 조직 설정에 "보안 센터(베타)"라는 페이지가 생겨서, 채팅·코워크·클로드 코드 각 설정값을 앤트로픽이 권장하는 값과 나란히 보여주고 바로 해당 설정으로 이동할 수 있게 해준다. 보고서로 다운로드해서 감사팀에 공유하는 것도 가능한데, 앤트로픽은 이게 "인증이나 법적 준수를 보장하는 게 아니라 권고 사항일 뿐"이라고 선을 그어놨다. 둘째, "추론 훅(inference hooks)"이 정식(GA) 출시됐다. 프롬프트 훅과 도구 호출 전(pre-tool-call) 훅 두 종류로, 기존에 쓰던 DLP·보안 정책 도구를 클로드의 프롬프트·도구 호출 단계에 그대로 연결할 수 있게 해준다. 셋째, IP 허용목록을 이제 앤트로픽을 거치지 않고 엔터프라이즈 관리자가 직접 설정·관리할 수 있다 (이것도 베타). 같은 주 11월 6일에는 "프로젝트 태그로 비용 코드별 지출 추적(베타)"이라는 작은 업데이트도 올라왔는데, 청구 코드나 클라이언트 매터 번호 같은 걸로 프로젝트에 태그를 달아 지출을 나눠볼 수 있는 기능이다.

## 오늘의 생각

두 소식 다 "화려한 신모델 발표"는 아니지만, 결이 비슷하다. 하나는 에이전트가 가질 수 있는 과도한 권한(내 이메일을 맘대로 네트워크로 보낼 수 있는 것, 묻지도 않고 권한 프롬프트를 통과시키는 것)에 브레이크를 다는 쪽이고, 다른 하나는 기업이 클로드를 조직 전체에 풀어놓을 때 "이게 어디까지 하는지, 어디서 막아야 하는지"를 한눈에 보게 해주는 쪽이다. 결국 둘 다 "에이전트가 더 많은 일을 자율적으로 하게 될수록, 그만큼 사람이 통제권을 쥐고 있다는 느낌을 줘야 한다"는 같은 문제의 다른 해법처럼 보인다. 화려하진 않아도, 매일 터미널에서 클로드 코드를 켜놓고 일하는 사람에게는 이런 작은 변경들이 쌓여서 체감 안정감을 만든다.
